# Main navigation and motion

The header holds the date/weather, status chips, clock and a quick-settings button; there is no top navigation bar. The button opens a separate quick-settings sheet (Settings, start at login, VPN, exit, shut down), which follows the focus/selection distinction and the elevated selected state described in Apple's [focus guidance](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection). This is a web implementation inspired by those patterns, not a native tvOS component.

`navigation-menu.js` owns the sheet lifecycle, its moving focus lens and the header button spring. Legacy `model.menu.groups` (Home / Library / category items) are ignored.

Up from the top tile row reaches the header buttons (VPN chip, quick settings); left/right moves between them and down returns to the grid. Back from the grid focuses the quick-settings button; back or Start there opens the sheet, which immediately focuses its first action (Settings). The sheet traps Tab, marks the content inert, and restores the previous focus on close. Real pointer movement can change focus; a parked cursor cannot steal D-pad focus while elements animate beneath it.

`menu-motion.js` integrates damped springs in small time steps, samples trajectories at 120 Hz and passes transform/opacity keyframes to Web Animations API. Playback needs no JavaScript animation loop or per-frame style writes. Retargeting samples the current animation position and velocity, so reversal preserves momentum. Stale completion callbacks cannot dismiss a reopened sheet. The default spring uses stiffness 420, damping 32 and unit mass; sheet opening uses stiffness 360. Per-sample interpolation is linear, but the trajectory itself is the physical spring solution, not a linear/ease focus transition.

The glass material remains on a stationary pseudo-element while the focus lens, item scale and text/icon parallax animate independently. Background images retain the existing decoded, double-buffered crossfade below the menu. No content container is transformed to open the sheet, and menu geometry remains fixed during slideshow changes. `menu.css` is scoped to menu/header elements and adds no tile or hero selectors. It includes opaque material fallbacks, reduced transparency, reduced motion and short-window scrolling for the sheet.

Run `node --test test/menu-motion.test.js` for physical convergence at 60/120 Hz, momentum preservation, cancellation, reduced motion and category behavior. Run `node scripts/verify-menu.cjs` in a desktop session for actual Electron keyboard and Gamepad API polling, filtering, modal/focus restoration, rapid reversal, responsive geometry, screenshots and frame diagnostics. Screenshots are written to `%TEMP%/vibepollo-menu-preview` by default, with `VIBEPOLLO_MENU_OUTPUT` as an optional destination override. The runtime check opens a temporary visible test window and does not change the normal launcher profile.

`VIBEPOLLO_MENU_VARIANT=control` runs the same frame sample with a moving 8×8 px control instead of menu animation. `VIBEPOLLO_MENU_NO_BLUR=1` disables only the bar blur during the timing sample. These diagnostic modes do not change production configuration. Captures are taken after timing to avoid GPU readbacks during the sample. The script prints idle/active rAF intervals, focus setup time, native animation counts and graphics details. These measurements are evidence, not a claim that every device sustains 60/120 fps. In this Windows session, control animation also showed frame-pacing spikes; the target frame rate therefore remains a hardware/runtime validation item.

## Quick-settings sheet (Q1)

The sheet is a right-hand side sheet with no backdrop blur: a near-opaque surface (`--panel-surface`), one transform-only focus lens (`.system-focus-lens`, accent-tinted, white text) and subtitles that wrap to two lines. Keep new rows to `.menu-action` with `.menu-symbol`, `.menu-copy strong/small`; use `vpnSubtitle`-style helpers for dynamic captions rather than relying on ellipsis. Settings is the first focusable row and the only entry point to the Settings dialog. Frame budget and measurement: `scripts/bench-ui.cjs`, see backend/MENU-PERFORMANCE.md.
